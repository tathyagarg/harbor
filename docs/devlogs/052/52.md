# Changes
---
- [3d51ba2](https://github.com/tathyagarg/harbor/commit/3d51ba29f82fd6a51dcb55cd10b1dde75e135cfc): Added parsing for while statements and do-while statements. Statement parsing is very simple :)
- [28d1bfe](https://github.com/tathyagarg/harbor/commit/28d1bfe3dcb9018d42ee782349dc9d8dbf071b38): Added parsing for return statements too, statement parsing is not complete!
- [09ffb36](https://github.com/tathyagarg/harbor/commit/09ffb369d3c636f451561406779c4a8c77428047): Added corresponding FFI structures to the Rust side. Honestly I thought all my work in making structures for expressions would be wasted but I doing this proved otherwise. Also I remembered that the runtime would be in rust so this was a necessary step.
- [6a525c2](https://github.com/tathyagarg/harbor/commit/6a525c2ab89c5a95cea6d12ba8c17ffc3920b438): Spent a LONG time trying to ensure that my FFI was working as intended. This involved writing a lot of functions to print the structures I was receiving. Worked out in the end, FFI is working as intended and I can now receive statements from the Zig side and print them on the Rust side.
- [07ee1dc](https://github.com/tathyagarg/harbor/commit/07ee1dc38a99d62e7eb5a543fa7eaaf7dd3b2622): The JS [ECMAScript specification](https://tc39.es/ecma262/) defines lots of functions, which I started implementing here. This will be useful for me to get an idea of what other structures I need to implement for the runtime.
